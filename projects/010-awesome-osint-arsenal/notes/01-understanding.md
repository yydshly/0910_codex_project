# Awesome OSINT Arsenal：完整理解

## 核心结论

它把第三方情报与安全工具的资料整理在一起，并提供批量下载或安装部分工具的脚本。价值在于发现与准备工具，查询和分析由你另外选择、配置、启动的工具完成。

“内置工具”准确地指“内置工具目录与部分安装条目”。不是各工具的程序、数据库与运行服务都已经装进这个仓库。

## 三个核心能力

| 能力 | 输入 | 处理 | 输出 |
| :--- | :--- | :--- | :--- |
| 工具发现 | 使用者的问题或类别 | 人阅读 README 分类与说明 | 候选工具、资料和外部入口 |
| 结构化目录 | 程序读取 tools.json | 获取名称、描述、分类、获取方式、标签等 | 可用于检索、统计的数据 |
| 环境准备 | 用户运行分类安装脚本 | 检测 Linux，调用包管理器、Git、pip、Go、Docker 等 | 软件、源码或镜像，以及安装状态统计 |

原库没有统一的目标输入界面、通用调查任务队列、跨工具结果模型或统一调查报告引擎。网页的中文搜索、过滤和场景讲解是本研究新增的展示功能。

## 安装原理与边界

`install.sh` 检查 root 身份，依次运行 OSINT、红队、蓝队、取证、硬件、练习与额外资源的分类脚本。Termux 另有脚本。

以 `osint.sh` 为例：

- `detect_distro()`：识别 Linux 发行版，选择 apt、pacman 或 dnf。
- `pkg_install()`、`install_pip()`、`install_go()`：检查并调用对应安装工具。
- `install_git()`：克隆到 `/opt/osint-arsenal/`；通常没有继续构建和配置各项目。
- `install_docker()`：下载镜像，不启动应用。
- `print_summary()`：打印成功、跳过和失败计数。

因此“下载成功”不等于“工具可用”。`osint.sh` 累计失败计数，但末尾没有按该计数明确返回失败码。总脚本把子进程正常退出记作模块成功，不能据此证明所有工具都可用。

检查固定版本九个 shell 脚本，未发现其引用 `tools.json`。JSON 目录与脚本中的安装条目分别维护，修改 JSON 不会自动改变安装列表。

## 代表工具：具体工作由谁完成

下表是依据上游目录整理的用途说明，不代表本次运行效果。

| 工具 | 需要提供 | 可能得到 | 边界 |
| :--- | :--- | :--- | :--- |
| Maigret / Sherlock | 账号用户名 | 同名账号候选、链接 | 同名不证明同一个人 |
| ExifTool | 文件 | 实际存在的作者、设备、时间、位置等元数据 | 没有的字段不能凭空恢复 |
| TinEye | 图片 | 已索引的相关图片来源 | 不保证覆盖全网或确定原创者 |
| Amass | 域名和配置 | DNS、子域名与关联线索 | 归属和覆盖需要核验 |
| Shodan | 查询条件及服务访问条件 | 已索引联网设备信息 | 外部服务可能需要账号、额度，信息有时效性 |
| Nmap | 自有或获授权目标 | 端口与服务检测结果 | 主动检测，与查询公开索引不同 |
| OpenCorporates | 公司名与地区 | 覆盖范围内的登记记录 | 外部数据库，原仓库不持有这些数据 |
| CyberChef | 数据及处理步骤 | 转换、解码等结果 | 步骤与结果解释仍需选择 |
| YARA | 文件与规则 | 特征匹配结果 | 命中不自动证明恶意 |
| Volatility | 支持的内存镜像 | 进程等取证线索 | 不是普通文件搜索器 |
| Wireshark | 网络数据包 | 协议与通信分析视图 | 原库不会自动抓取或分析 |
| Ghidra | 程序文件 | 程序结构、反汇编等信息 | 需要专业解释 |
| MISP | 情报来源与配置 | 情报组织与关联 | 需另行部署、维护 |
| OWASP Juice Shop | 单独准备的环境 | 有意包含漏洞的练习应用 | 本页没有启动该应用 |

## 六个场景

1. **检查图片信息**：找到 ExifTool、TinEye，区分文件元数据和图片来源搜索。
2. **查同名账号**：找到 Maigret、Sherlock，另行运行后核验候选。
3. **了解自有域名**：找到 Amass、Shodan、Nmap，先区分公开索引和主动检测。
4. **查企业资料**：找到企业数据库入口，确认覆盖地区与主体。
5. **分析已有文件**：先辨别文本、普通文件、内存镜像，再选匹配工具。
6. **组织学习路径**：按协议、程序、Web 安全等目标选择工具与练习平台。

网页只演示输入类型、候选工具、预期输出类型、边界和职责分工，不显示虚构账号、图片字段或检测结果。

## 是否必须 Linux

阅读目录、使用本研究页面不需要 Linux。原库主安装脚本主要面向 Linux；Windows 可通过已准备的 WSL 或虚拟机运行。第三方工具是否支持 Windows 取决于各工具。本次按要求不继续安装。

## 可扩展方向（建议，尚未实现）

1. 清洗工具目录，并以同一份数据生成网页与安装清单。
2. 增加版本、验证日期、费用、账号要求、平台及输入输出约束。
3. 对少量工具隔离安装并做功能验证，再增加覆盖。
4. 为研究助手接入已验证工具，保留来源、采集时间与原始证据。
5. 进一步实现任务串联、去重与报告；这些不是原库现有能力。

## 对当前研究的意义

作为候选工具地图，它可以减少寻找入口的时间。已经选定 Maigret 等工具后，应主要阅读那个工具自己的文档与代码。对于研究助手，它提供选型材料，不应直接当作可信的自动执行清单。
