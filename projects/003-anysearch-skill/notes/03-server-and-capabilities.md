# 服务端、当前能力与原理边界

补充研究日期：2026-09-10。

## 本地技能与远端服务的关系

AnySearch 团队提供运行中的远端搜索 API，入口为 `https://api.anysearch.com`。本仓库提供连接它的技能说明和客户端。用户使用时不需要自行架设搜索后端。公开文件无法判断实际部署是一台服务器还是多个服务或集群。

前面的客户端研究主要解释宿主 Agent 如何选择领域；服务端还有自己的处理层。[官网首页](https://www.anysearch.com/home) 声明了多来源统一接入、自动意图识别、分层路由、弹性编排、跨领域重排、质量评分与结构化输出。这些是官方对产品能力的描述，不是后端实现已开源或算法效果已独立验证。

## 后端原理可以确认到哪里

从产品说明和接口形态看，它可理解为一个统一的检索与数据查询入口：请求携带 query、tag 和 params，服务按能力选择查询路径，访问相关数据来源，再整理返回结果。官网进一步声明具有路由与重排机制。

在线目录有具体的数据来源线索：学术参数提及 S2 数据库、Crossref 映射、PubMed/MEDLINE 和 PMC；专利描述提及 EPO DOCDB/INPADOC；农业描述提及 FAO；代码描述提及 GitHub 与 npm/PyPI/Cargo 文档生态。金融新闻参数可选择新浪、东方财富、财联社等来源。

这些说明支持“对接多种专业数据来源”的理解，但不能证明每次请求具体访问了哪个供应商，也不能确定采用直连 API、缓存、自建索引、网页抓取或混合方式。通用网页搜索是否使用 Google/Bing/Brave，以及向量检索、模型选择、重排算法和抓取实现，当前证据不足以确认。

以论文问题为例，典型工作流是：Agent 选择 academic.search 并填写年份等筛选参数 → 客户端提交请求 → 服务端按能力查询相关来源并整理结果 → Agent 使用标题、摘要和来源回答。其中服务端内部具体步骤是基于接口与官方说明的概念解释，不是已审计源码。

## 书籍查询补充

如果“搜书”确实指书籍：当前学术目录的类型筛选包含 book、book-chapter，引用能力支持 ISBN 标识符。它们指向书籍元数据或引用信息查询，未实际测试；目录未显示独立电子书全文下载能力。

## 对既有研究的补充

官网目前展示了与 Brave、Parallel 的自报评测，注明使用 Frames、FreshQA、WebwalkerQA 共 300 题。因此应区分“仓库检查中未发现质量基准”与“官网没有任何评测”；后者不成立。本研究没有复现官网评测，也未检查完整实验材料，不将宣传分数作为独立验证结果。
