# 完整理解：能力、本质与意义

研究日期：2026-09-10。Memmy commit：`98146714aad8569a298cf8692946da8bb28bf7cb`，主项目版本 `1.1.4`。以下区分源码事实与我们的分析；未实测上游行为与效果。

## 1. 本质是什么

共享记忆部分是面向 Agent 的采集、存储、整理与检索服务。Memmy 通过适配器连接不同工具，把相关历史作为上下文交给执行中的 Agent，还带有自己的 Runtime、桌面工作台、CLI 和 API。

我们的理解是：**增加适配接入层，统一记录并保存；任务需要时取回经验；对应 Agent Runtime 实际执行；新结果再进入记忆系统。**

不是所有阶段都串行阻塞当前任务。原始记录先保存，摘要、向量化和高层提炼可以后台运行。历史导入有处理就绪条件，不能把“写入成功”直接等同于“立刻可被完整检索”。

关于“仍然是 Agent 那套机制，只是提取到外部”的进一步理解，见[外部记忆架构汇总](07-external-memory-architecture.md)：独立的是记忆管理职责，很多内部环节属于程序流程和模型辅助工作流，当前任务的执行循环仍由对应 Runtime 负责。

## 2. 已有能力

| 能力 | 具体作用 | 边界 |
| --- | --- | --- |
| 多来源记忆 | 扫描多个 Agent 本地历史，并支持新对话采集 | 只覆盖已配置、已接入或已发现的来源 |
| 共享召回 | 接入的 Agent 查询同一份服务 | 依赖范围设置与宿主集成 |
| 任务续接 | 搜索历史任务并加载过程作为上下文 | 不自动复制代码、进程或依赖环境 |
| 经验提炼 | 从记录归纳规则、环境知识与技能指南 | 模型归纳可能有误，需核对证据 |
| 记忆管理 | 查看、删除、检查来源与日志；Dream 整理和恢复 | 不代表全部记忆质量问题已解决 |
| 独立 Agent | 模型调用、文件与命令工具、MCP、会话与任务管理 | 自带 Runtime 与外部接入是不同用法 |

来源：[官方功能清单](https://memmy.bot/docs/concepts/features/)、[固定版本 README](https://github.com/MemTensor/memmy-agent/blob/98146714aad8569a298cf8692946da8bb28bf7cb/README.md)。在线文档会更新，代码分析以固定提交为准。

## 3. 谁决定，谁执行

| 工作 | 谁负责 |
| --- | --- |
| 是否采集、何时查询 | 用户操作、适配事件、宿主策略或模型按需调用 |
| 怎样存储与检索 | Memory 服务 |
| 怎样提炼经验 | 后台管线、规则和配置模型 |
| 当前任务做什么、调用什么工具 | 对应 Agent 的模型与 Runtime 协作 |
| 实际执行工具、接收结果 | 外部 Runtime 或 Memmy Runtime |

模型提出工具调用，运行环境实际执行。共享记忆不意味着 Memmy 统一指挥所有外部 Agent。

## 4. 理解纠偏

| 容易产生的理解 | 更准确的表述 |
| --- | --- |
| 每个接入工具都会自动召回 | 接入深度不同，有的依赖 Skill 按需查询 |
| 本地数据库意味着全程离线 | 摘要、Embedding、过滤和演化可以使用远程模型 |
| 自进化就是训练模型 | 所研究流程更新记忆评分、经验内容和技能指南 |
| L3 World Model 是世界模拟模型 | 此处主要表示项目、环境和约束知识 |
| 生成 Skill 就能可靠执行 | 指南需要真实任务验证、反馈与维护 |
| Memmy 是 Mnemosyne 的封装 | 两者独立；更多封装指产品范围，并非依赖关系 |

来源：[集成差异](https://memmy.bot/docs/memory/sources/)、[配置与模型调用](https://github.com/MemTensor/memmy-agent/blob/98146714aad8569a298cf8692946da8bb28bf7cb/Memory/readme.md)、[奖励更新](https://github.com/MemTensor/memmy-agent/blob/98146714aad8569a298cf8692946da8bb28bf7cb/Memory/src/service/evolution/reward-pipeline.ts)。

## 5. 使用场景（我们的推导）

- 多个编程工具交替使用：共享项目背景、历史决策与排错经验。
- 持续多周的工作：找回已尝试方案和未完成步骤。
- 重复工作：积累数据处理、发布检查、排错经验。
- 个人研究：保存主题、约定和结论，帮助后续比较。
- 自建 Agent：复用独立记忆服务与适配器的接口思路。

对本 GitHub 研究库，可记录项目版本、采用条件、已验证能力和研究方法，再用相似项目比较任务验证是否减少重复研究。正式结论仍保留文档和原始来源；历史需结合当前源码复核。

## 6. 架构意义（我们的分析）

1. **记忆与 Agent 分开**：切换工具时仍能访问已有经验。
2. **适配层隔离差异**：不同历史格式与事件接口不侵入核心。
3. **后台加工与执行分开**：无需等待所有提炼完成，失败可单独重试。
4. **记录进一步变成方法**：从旧对话提炼出带适用条件的操作参考。
5. **召回后再注入**：控制上下文体积和噪声。
6. **保留来源和反馈**：有条件解释、纠正和停用经验。

这些是潜在收益，不能替代评测。关键验证是：记忆是否可靠、召回是否相关、执行是否依据当前事实重新判断。

## 7. 扩展方向

官方路线图包括更多来源（浏览器、本地文档及更多设备）和带隐私保护的团队协作，应标为规划。[固定版本路线图](https://github.com/MemTensor/memmy-agent/blob/98146714aad8569a298cf8692946da8bb28bf7cb/README.md#roadmap)。

以下是我们的建议：

| 方向 | 补充内容 | 验证方式 |
| --- | --- | --- |
| 效果评测 | 有记忆 / 无记忆对照 | 成功率、错误引用、耗时、成本 |
| 版本与证据 | 来源 commit、环境、失效与重验证 | 旧经验是否误用于新版本 |
| 更多知识来源 | 研究文档、Issue、PR、会议记录 | 覆盖率、来源是否可回查 |
| 技能验证 | 任务回放、审核、版本与撤销 | 新任务真实执行结果 |
| 团队共享 | 范围、授权、撤销与审计 | 隔离与删除传播 |
| 大规模检索 | 候选窗口、索引和存储 | 长期积累后的旧记忆召回 |

具体限制：当前 SQLite 向量搜索以匹配条件下最近 2,000 条向量记录组成窗口。这不是存储上限，但影响旧记录能否进入向量候选；全文等通道是另一路径。来源：[窗口定义](https://github.com/MemTensor/memmy-agent/blob/98146714aad8569a298cf8692946da8bb28bf7cb/Memory/src/storage/sqlite-vec-store.ts)、[查询实现](https://github.com/MemTensor/memmy-agent/blob/98146714aad8569a298cf8692946da8bb28bf7cb/Memory/src/storage/repositories.ts)。
