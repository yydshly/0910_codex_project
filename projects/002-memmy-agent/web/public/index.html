01B / EXTERNAL MEMORY GUIDE

Agent 继续做任务，记忆独立成服务

“还是 Agent 那套机制，只是提取到外部”抓住了能力独立的方向。更准确地说，独立出来的是记忆管理：采集、保存、整理、检索与更新。当前任务的模型与工具循环，仍由对应 Agent Runtime 负责。

AGENT

推进当前任务

模型结合上下文提出行动，Runtime 执行工具并读取结果。历史会影响判断，但当前仓库、环境与真实结果仍需核对。

ADAPTER

连接不同宿主

Hook、插件或 Skill 转换事件与格式，传递问题、上下文和完成记录。接入方式决定何时查询或写回，不保证所有宿主每轮自动调用。

MEMORY

管理长期经验

保存可追溯记录，多路检索并筛选上下文，后台总结、索引、评分和提炼。它提供参考，不直接取得外部 Agent 的工具执行权。

三个容易混淆的地方

职责边界比“是否用了模型”更重要
“外部”不一定是另一台服务器
它独立于 Agent 的临时会话状态，可以仍运行在同一台电脑。模型是否远程调用是另一项配置。
使用 LLM 不等于整个模块都是 Agent
摘要和归纳会使用模型；存储、检索排序和排队重试主要是程序流程。是否承担目标推进与行动闭环，需要另看职责。
服务化也不只是外接数据库
适配、数据组织、检索筛选和更新机制共同形成记忆能力。仅保存聊天文本不足以保证有效召回或正确使用。
结构独立不代表从某个 Agent 搬出代码
这里描述的是架构边界，没有据此推断项目的代码演变历史。Memmy 也不是 Mnemosyne 的二次封装。
按一次任务理解：查询 → 使用 → 回写 → 更新
  1. 用户向原 Agent 提问，宿主按自己的集成策略发起记忆查询。
  2. 适配层提交问题与会话信息，Memory 返回筛选后的历史上下文，也可能无命中。
  3. 原 Agent 将参考材料用于自己的模型与工具循环，结合当前事实继续任务。
  4. 完成后采集真实结果；支持生命周期的入口可使用 turn.complete。开始召回本身不等于已经保存最终对话。
  5. Worker 异步加工，符合就绪和筛选条件的材料供后续任务使用。
独立记忆的意义

跨会话保留、跨工具复用、独立管理和后台加工。前提是采集完整、记录可靠、召回相关、宿主正确使用；不能以写入成功代替整条链路成功。

本图聚焦外部接入。Memmy 自带 Runtime 是另一种任务执行端，不是外部 Agent 接入必须经过的中间节点。Mnemosyne 也提供服务与集成能力；“更多封装”描述产品范围，不代表已验证效果更优。

02 / INSIDE THE SYSTEM

从一次执行，到下一次经验

技术的作用，是让历史可保存、可组织、可找回，再成为当前任务的参考。

A

先记录，再后台加工

用会话、轮次、稳定 ID 和检查点整理历史、去重并保留来源。原始记录保存后，Worker 再做摘要、向量化和提炼；失败任务可以重试。

写入成功不等于完整索引已经就绪。历史导入会等待处理条件满足后进入召回。

B

语义与精确线索一起查

SQLite 保存正文与元数据；FTS5 查关键词；sqlite-vec 查语义相近的向量。短片段和结构线索补充中文短词、路径和错误码匹配。

本地 Embedding 使用 Transformers.js，也可以配置远程向量服务。

C

选出值得带入的内容

RRF 综合不同通道排名；质量与时间权重考虑经验价值和新旧；MMR 减少重复；模型按配置进一步过滤候选。

返回的是历史上下文。当前请求和实际仓库状态仍需优先核对。

“自进化”发生在经验层

所研究管线更新记忆评分、规则和操作指南，不训练大模型参数。不是每条记录都会变成技能；生成指南也不意味着已通过真实任务验证。

补充：两种调度与整体技术栈

Worker 调度安排摘要、索引、评分与提炼。Agent Runtime 调度组织用户任务，调用模型、执行工具并处理结果。两者可以配合，但不是同一条循环。

Memmy 主体使用 TypeScript / Node.js。桌面使用 Electron、React、Vite；本地管理后端使用 Fastify、SSE 管理配置、集成与进度。Memory 服务、管理后端与 Agent Runtime 是不同模块。

一次请求具体如何流转

支持回合生命周期的接入路径；不是所有宿主的统一行为
  1. 准备会话与请求

    宿主打开或复用会话，以当前问题调用 turn.start。会话标识用于关联上下文，来源标识用于追溯工具。

  2. 判断是否需要历史

    记忆服务结合任务意图、检索模式和范围选择候选。闲聊等请求可跳过召回；没有结果不应编造历史。

  3. 返回经过筛选的上下文

    检索和过滤后返回 turnId、命中及可用的 injectedContext。当前请求与历史参考分开传入宿主。

  4. 由对应 Agent 实际执行

    宿主或 Memmy Runtime 调用模型、执行工具、接收结果；记忆服务不会因此取得外部 Agent 的统一调度权。

  5. 结束后保存真实结果

    turn.complete 关联轮次、请求、回答及结果，确定最终 episode 归属并持久化。开始召回并不等于已经保存最终对话。

  6. 后台加工，为后续任务准备

    Worker 按配置总结、评分、索引和提炼。导入记录须满足就绪条件；并非本次结束后所有高层经验立即可用。

查看接口职责和最容易混淆的细节

turn.start 需要已有会话和查询；它返回轮次标识，可包含历史上下文。在该版本的接口说明中，开始阶段不创建 RawTurn、L1 或演化任务；这些在完成时处理。

turn.complete 使用返回的轮次标识关联实际请求与回答。手动 CLI 和宿主插件对失败、取消的支持不完全一致，不能把某个接口的状态规则套到所有适配器。

memory.search / memory.add 是按需查询与写入，不要求调用方一定经历完整的 turn 生命周期。Session、Turn、Episode 分别表示会话、单轮交互和相关任务过程，不能当作同一个 ID。

03 / HOW MEMORY WORKS

记忆如何保存、找回，再变成经验

核心原理：把执行过程保存在模型之外，整理并建立索引；新任务到来时检索有关记录，作为上下文交给 Agent。后台再根据结果和反馈更新经验。

三个东西共同构成一条可用记忆

向量帮助找内容，正文保留实际含义
CONTENT

正文与执行记录

保存请求、回答、工具结果、摘要或规则。SQLite 中的 raw_turns、memories 等表承载这些材料。

CONTEXT

来源、状态与关联

会话、episode、层级、标签、版本与时间解释“这条记忆从哪来，何时适用”。哈希与稳定 ID 帮助去重。

INDEX

全文与语义索引

FTS5 按词查找；Embedding 将文字编码成数字向量，再由 sqlite-vec 等实现寻找相近内容。向量不能代替原始证据。

关键技术，各自解决什么问题

Memory 子包 2.1.2 · 固定研究提交
SQLite + better-sqlite3
保存正文、关系与处理状态，通过 SQL 和索引查询。本地持久化解决跨会话保存。
Embedding + Transformers.js
把查询和记忆编码为可比较的向量，连接措辞不同但语义相近的问题。模型可配置为本地或远程。
FTS5 + 短片段 / 结构匹配
用关键词、中文短词、路径和错误线索补充向量召回，避免只看大致语义而遗漏精确信息。
RRF + 质量与时间权重
综合各通道排名，再考虑经验价值、层级与新旧程度。原始相似度、关键词得分无需直接相加。
MMR + 可选 LLM 过滤
MMR 平衡相关性和重复度；模型过滤再结合当前问题筛选。结果可以为空，相似并不代表正确。
Worker + 持久化队列
异步摘要、评分、向量化和经验提炼；记录任务状态并支持重试。保存成功不等于全部索引就绪。
LLM 结构化生成
从记录生成摘要、反思、L2 规则，以及符合条件的 L3 知识或 Skill。生成结构与证据检查不等于真实任务验证。
TypeScript / Node.js + tiktoken
前者组织服务与管线；后者参与部分摘要和向量输入的 token 估算。桌面界面技术不构成记忆机制本身。
展开算法：RRF 与 MMR 到底做了什么？

RRF 按名次融合。基础项为 Σ 1 / (k + rank)，这里名次从 1 开始。某条记录在多个通道靠前，就得到多份贡献。实际实现还结合层级、质量和衰减等因素，这不是完整的最终评分公式。

MMR 逐条选择。计算 λ × 相关性 − (1 − λ) × 重复度。重复度参考候选与已选向量的最大余弦相似度，让有限上下文包含更多互补信息。

先筛范围，再排顺序。意图、来源范围、层级与就绪状态会影响候选资格；阈值、去重和可选模型过滤继续缩小结果。当前向量路径的 2,000 条候选窗口也会影响检索范围。

EXAMPLE / 仅为原理示意

“项目又因为配置缺失启动失败了”

语义检索找到“缺少环境变量”的相近经历，全文找到精确配置名，结构线索补充错误码；融合和去重后，保留有关的历史修复步骤与适用条件。

Agent 收到这些参考，仍需检查本次配置。任务结束后，真实结果成为新记录；合格证据可以推动规则更新。这里没有运行真实检索，也没有编造命中分数。

记忆能力来自整条链路

从架构上可理解为面向执行经验的检索增强与生命周期管理。反馈更新的是记录、价值和指南，不是底层模型参数；分数衰减也不等于自动物理删除。

数据表与状态结构 ↗ 向量编码实现 ↗ 检索融合与 MMR 算法 ↗ 结果反馈与价值更新 ↗
04 / MNEMOSYNE × MEMMY

相似的记忆思路，不同的产品范围

Mnemosyne 提供可接入应用的记忆组件。Memmy 增加了更多适配、后台服务与自带 Agent。两者独立，Memmy 不是对 Mnemosyne 的二次封装。

对比维度Mnemosyne记忆组件与服务Memmy Agent共享记忆与 Agent 应用
接入方式Python SDK、MCP、专用插件Hook、插件、Skill、HTTP API、CLI
写入触发宿主程序、工具调用或集成事件历史扫描、适配采集与按需写入
记忆组织工作记忆、长期摘要；事实与时间关系L1 执行记录、L2 经验、L3 环境知识、Skill
整理方式核心 sleep() 同步执行，自动调度由集成提供后台任务、重试与经验管线；另有 Dream 整理
真实执行由宿主 Agent 负责外部模式由宿主执行；自带模式由 Memmy 执行
工程形态Python，可嵌入同一进程或作为服务TypeScript / Node.js，包含桌面和本地服务

不能简单理解为“一个手动，一个自动”。Mnemosyne 的 Hermes 集成也有自动采集、注入与整理；Memmy 各宿主的自动化程度也不同。

功能范围更广，不代表效果更好。这里比较职责和结构，没有对测检索质量、执行成功率或性能。

不同宿主的自动化深度
  • Claude Code / Codex：该研究版本提供 Hook 接入，支持普通请求前的召回与完成后的采集。
  • OpenCode / OpenClaw / Hermes：通过各自插件或 Provider 接口接入，采集字段与生命周期事件因宿主而异。
  • Cursor：Hook 重点是自动采集和任务续接，普通请求额外查询主要依靠 Skill。
  • WorkBuddy / Pi / qwenwork：所列方案主要通过 Skill 按需读写。安装成功仍需要在实际宿主版本中验证。

这是 Memmy 固定版本中的适配说明，不是对这些宿主当前所有版本的兼容性保证。

05 / WHY IT MATTERS

一次工作，留下结果，也留下经验

记忆不再绑定一个工具

不同 Agent 访问共享服务，切换工具后仍有机会找回项目背景和历史决策。

连接差异留在适配层

历史格式与宿主事件各不相同，接入层承担转换，核心记忆逻辑可以复用。

将旧过程变成新参考

摘要帮助找回过去，规则和指南帮助组织下一次任务。后台加工减少对当前执行的等待。

对我们的 GitHub 研究库

带着已有研究，理解下一个项目

保存研究版本、已验证能力、采用条件和比较方法。遇到相似项目时取回相关结论，辅助分析；正式文档仍保留来源，旧结论仍需复核。

研究项目 A→沉淀结论与方法→辅助比较项目 B

这是应用设想，不是已经接通的功能。也适用于多工具编程、长期项目、重复排错与个人知识积累。

以后实现类似能力时，分别借鉴什么

  • 保存、整理、检索接口参考 Mnemosyne 的接口与数据组织。
  • 多工具采集与任务续接参考 Memmy 的适配和任务生命周期。
  • 经验转化为操作指南参考 Memmy 的证据、评分与技能提炼。

保留架构与源码入口，开发类似能力时再深入。先验证是否减少重复解释，再决定是否增加向量、摘要和跨工具自动化。

06 / LIMITS & NEXT STEPS

理解边界，才能判断价值

本地存储 ≠ 全程离线

摘要、Embedding、过滤和提炼可以调用远程模型。实际数据流取决于配置。

共享上下文 ≠ 迁移执行环境

任务续接提供历史，不自动迁移代码、依赖或运行中的进程。

旧经验必须重新核对

来源、项目版本、环境和有效时间决定是否适用。错误记忆可能反复影响后续任务。

规模增长需要重新评测

当前 SQLite 向量路径使用最近 2,000 条匹配向量的候选窗口。这不是存储上限，但可能影响旧记录召回。

官方规划

扩展浏览器活动、本地文档及更多设备来源；探索带隐私保护的团队 Agent 协作。

路线图，不视为已验证能力

我们的扩展建议

记忆效果对测、版本与证据管理、更多知识来源、技能任务回放、团队权限，以及大规模检索优化。

研究建议，不是上游承诺

失败时，会发生什么

行为依赖配置与调用入口

记忆服务暂时不可用

官方适配说明采用 fail-open：记录错误，让宿主继续当前任务。继续执行不等于历史已成功加载或本轮已保存。

查询向量生成失败

全文、短片段和结构线索可继续提供候选；召回质量仍可能变化。写入后的向量生成失败则进入重试路径。

模型过滤失败或无命中

无模型、调用失败或返回格式无效时，可退回机械排序候选；模型合法地筛掉全部候选时，可以没有历史上下文。

旧经验不适合新环境

查看来源和版本，验证当前事实，再修正或停用经验。这是使用与评测要求，不能把现有评分当作真实性证明。

哪些内容可能离开本机，以及如何评测收益

本地：历史文件读取、SQLite 记录和索引管理。按配置调用模型：当前任务上下文、摘要材料、Embedding 文本、候选过滤片段和经验提炼证据。使用远程 Provider 时，相应材料会成为模型请求的一部分。

Memory HTTP 的 token 鉴权依配置启用；命名空间和 source 标识本身不能当作完整团队权限系统。

建议评测：固定同一任务、代码版本、模型和工具环境，对比不启用记忆与启用记忆两组。记录任务成功率、错误历史引用、来源可追溯性、总耗时和模型费用。先观察真实收益，再加更复杂的索引与提炼。

最终看三件事：记忆是否可靠 · 召回是否相关 · 执行是否依据当前事实
