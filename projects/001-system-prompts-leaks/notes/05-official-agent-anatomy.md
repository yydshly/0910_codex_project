# Agent 包含哪些部分：以 OpenAI 官方天气助手为例

研究日期：2026-09-10。本文依据本次实际读取的 OpenAI 官方文档编写，与上游提示词档案的固定提交研究分开记录。未执行模型调用或真实天气查询。

## 1. 为什么选择这个样例

选择 OpenAI Agents SDK 官方文档中的 **Weather bot（天气助手）**。依据是产品方自己提供的 Agent 配置、工具函数和运行机制说明，属于一手资料。

“最权威”没有跨所有厂商通用的排名。对理解这个 SDK 的机制，官方定义与官方代码示例是直接依据。这个小样例足以区分模型、指令、工具和程序执行，也更容易明确哪些能力是后来增加的。

这不是 Codex 私有后端的复原，也不是对 System Prompts Leaks 中某份收录文本的真实性认证。它提供一个独立的官方参照，帮助我们正确解释归档材料。

## 2. 图中的最小运行组成

| 图中部分 | 作用 | 在官方示例或文档中的对应 |
| :--- | :--- | :--- |
| 用户任务与输入 | 提供本轮目标 | 运行器接收的输入；图中的“北京天气如何”是本站自拟问题 |
| 工作指令 | 描述助手职责和行为要求 | 天气助手的 `instructions` 配置 |
| 工具接口说明 | 告诉模型可调用的名称、含义和参数 | `get_weather` 的函数说明、城市参数及工具定义 |
| Runner 运行器 | 组织模型调用与工具执行，管理继续和结束 | 官方运行循环；Python 使用 `Runner.run`，TypeScript 使用 `run` |
| 模型 | 理解输入，生成回答或工具调用请求 | Agent 的 `model` 配置；模型名称与 Agent 产品应分开理解 |
| 工具代码和执行环境 | 真正执行调用、返回结果 | 天气函数的函数体以及承载它的程序环境 |
| 结果交付 | 将完成后的结果交给应用 | Python 的 `final_output`，TypeScript 的 `finalOutput` |

本轮输入、调用与结果需要在循环中被管理，这属于运行状态。跨轮会话如何持续保存，需要另外选择策略，不能自动推断已经有长期记忆。

这里展示的是**带工具的 Agent 工作流**。工具、转交与审批可以按需配置；不能把这张具体样例图理解为所有 Agent 的强制字段清单。

## 3. 一次运行如何推进

运行器准备输入并请求模型。若模型选择调用天气工具，程序执行函数，将结果提供给后续模型调用；如果还需要工具工作，就继续循环；当模型生成最终回答且没有后续工具工作时，运行器返回结果。运行还可能因配置的审批暂停，或因工具错误、验证失败、轮次上限等异常退出。

图中的调用路径属于根据官方循环编写的教学演绎，未记录真实执行轨迹，也不保证模型遇到同样问题一定选择同一条路径。

官方天气函数返回的是根据城市拼接的固定晴天文本，没有查询实时天气服务。它适合说明工具结构；若要提供真实天气，必须实现真实数据获取。由此可以明确：**给模型一个工具说明，与真正实现这个工具，是两个环节。**

## 4. 必须区分的上下文

**模型上下文**是显式送给模型的信息，如指令、用户输入、历史和工具结果。

**程序本地 context**可以承载已认证身份、数据库客户端、日志器或辅助函数，供应用代码与工具使用。官方文档明确说明，这些数据不会仅因为传入运行器就自动发送给模型。如果模型需要其中某条事实，应用需要通过输入、指令、检索或工具显式提供。

因此，“Agent 程序知道某件事”与“模型本轮看到了某件事”不能混为一谈。

## 5. 根据任务增加的工程能力

| 扩展 | 解决的问题 | 应保留的区别 |
| :--- | :--- | :--- |
| 会话保存 | 让下一轮接续已有交互 | Session、应用保存历史和服务端会话是可选择的方式；会话延续不等于修改模型权重 |
| 长期记忆 | 将有价值信息持续复用 | 筛选、检索、更新和过期处理需要应用设计，不是天气函数自带的功能 |
| 自动校验与人工审批 | 检查输入、输出、工具行为，必要时暂停等待决定 | 检查逻辑、审批和实际资源权限需要具体实现；自然语言约定不足以替代权限 |
| 多代理与任务转交 | 将不同职责分给专门角色 | 可以转交控制，也可以把专门角色作为工具；单个 Agent 不必有多代理 |
| 外部工具与 MCP | 接入其他服务与数据 | 工具定义之外，还涉及连接、认证、执行和结果回传 |
| 结构化输出 | 让下游程序获得约定格式 | 格式正确不能独自证明事实正确 |
| 追踪和评测 | 观察模型、工具、转交等执行过程并评价结果 | 运行记录提供证据，实际质量需要评测判断 |

这些属于 SDK 及相关应用的扩展设计，未全部配置在官方天气示例中。图中将它们放在单独区域，避免把“可增加的能力”画成“所有 Agent 都已经拥有的能力”。

## 6. 对我们的研究有什么帮助

读提示词档案时，可以把内容对应到工作指令、接口描述、上下文材料和流程约定。随后继续追问：哪个程序执行这些操作？状态保存在哪里？权限由谁控制？结果怎样反馈？效果有没有验证？

这让“研究 Agent”有了明确的分析层次。档案提供部分设计材料；可运行的助手还需要模型服务、运行器、工具实现、状态与权限配置，以及任务验证。部分档案附有配套代码，也需要逐项确认依赖和运行范围。
