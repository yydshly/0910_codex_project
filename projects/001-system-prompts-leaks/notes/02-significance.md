# 这个库的意义：从指令档案到可验证的 Agent 设计

研究日期：2026-09-10

固定上游版本：`f475e8b2b11ca7540a37234a451e9f085471bd94`

范围：基于已读取的公开仓库材料提出研究价值与迁移方法，未执行真实模型对照实验。

## 核心意义

这个库让部分 AI 产品的内部指令成为可阅读、可比较的研究材料。它帮助读者理解成熟 Agent 如何组织角色、任务、工具和上下文，再从中提出自己的设计方案。

上游主要提供原始提示词和配套资料的收集与归档。本研究站点进一步提供中文能力解读。将材料改写为适用自己的指令、实现工具、验证效果，则是后续开发工作。这三个环节不能混为一谈。

## 为什么值得研究

| 价值 | 具体例子 | 不能直接推出的结论 |
| :--- | :--- | :--- |
| 理解行为设计 | 在规划指令中看到“调查环境、澄清目标、形成方案”的安排 | 不能据此证明某次输出一定由这条规则导致 |
| 学习工程方法 | 研究 Explore 与 Plan 如何区分搜索和方案设计职责 | 不能只复制角色描述就获得完整多代理调度系统 |
| 设计自己的助手 | 把持续执行、上下文读取、记忆管理等规则适配到业务 | 不能保证原产品的规则在不同模型或工具下同样有效 |
| 建立研究证据 | 固定材料版本并提出可测量的效果假设 | 文本更新不必然代表能力变强，入库日期也不等于上线日期 |

这些价值是本研究的分析判断，实际收益仍取决于后续工作质量。

## 三个可以落实的方向

### 1. 能交付任务的编码助手

从持续执行与验证的指令中提炼完成标准：先理解代码，实施必要修改，执行相关检查，再报告结果与未解决问题。

还要提供读取、编辑、测试工具与结果回传。用固定缺陷任务比较完成率、误修改、耗时和成本，才能判断规则是否有用。

来源：[Codex 指令样本](https://github.com/asgeirtj/system_prompts_leaks/blob/f475e8b2b11ca7540a37234a451e9f085471bd94/OpenAI/Codex/gpt-5.4.md)。

### 2. 只读代码调查助手

从 Explore 的角色边界中提炼搜索职责：定位文件和符号，返回证据，明确搜索范围，不把片段阅读当作全面审查。

还要由程序提供真正的只读权限。用已知位置的任务验证准确率与遗漏率，并检查文件修改操作是否确实被禁止。

来源：[Explore 角色样本](https://github.com/asgeirtj/system_prompts_leaks/blob/f475e8b2b11ca7540a37234a451e9f085471bd94/Anthropic/claude-code/agents/Explore.md)。

### 3. 记住团队约定的助手

从记忆分类与检索规则中提炼长期信息管理方式，将稳定约定与当前任务临时信息分开。更新、过期和冲突处理属于需要结合自己业务设计的部分。

还要提供持久存储、访问控制、查找与删除入口。用多轮任务验证约定是否被正确应用，测试旧信息和跨项目误用。

来源：[Claude Code 指令中的记忆说明](https://github.com/asgeirtj/system_prompts_leaks/blob/f475e8b2b11ca7540a37234a451e9f085471bd94/Anthropic/claude-code/claude-code-opus-4.6.md)。

## 怎样研究更有结果

1. 选择一个具体任务和一份相关材料，确认来源、版本和适用环境。
2. 提炼少量可解释的规则，保留它们与原文的对应关系。
3. 改写工具名称、项目上下文和业务边界，去掉不适用的要求。
4. 实现配套工具与权限，先确认流程能够运行。
5. 固定模型、任务、工具、采样设置和预算，对比加入规则前后的结果。对随机性明显的任务进行重复试验。
6. 记录成功与失败案例，把规则和生效条件一起保存。

复制一份提示词可以成为实验起点。复现完整产品仍需要模型、工具、调度、状态管理和质量验证。更有价值的产出是“在什么条件下，哪条规则能改善什么行为”的证据。
