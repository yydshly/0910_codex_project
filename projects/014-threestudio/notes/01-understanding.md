# threestudio 完整理解

研究日期：2026-09-10；上游版本：`28d9d80d9d00f308244adfcf3be8b17ca0cb6465`。本文汇总本次讨论，并用固定配置与源码修正容易混淆的说法。代码存在与文档声明均不等于本地实测成功；完整证据见[来源表](03-sources-and-validation.md)。

## 它到底是什么

threestudio 是用文字、图片等条件生成和编辑三维内容的算法与工程框架。它统一组织已有的预训练模型、多种三维表示、渲染器和优化方法。框架中实现或复现了 DreamFusion、Magic3D、Zero123 等路线，但不意味着所有实现与原论文完全一致。

“它的核心是大模型还是算法？”需要从两个角度回答：库主要交付算法实现、模块和执行框架；视觉生成能力则来自预训练图像模型与这些算法共同工作。图像模型提供指导，算法把指导落实到三维表示上。

## 三种容易混淆的东西

| 名称 | 在这里的含义 | 举例 |
| :--- | :--- | :--- |
| AI 大模型 | 已经训练好的图像生成 / 视角条件模型，是程序加载的工具 | Stable Diffusion、Stable Zero123 |
| 任务输入 | 这一次要处理的素材或要求 | “一只戴红帽子的小猫”、去背景的猫图片 |
| 三维模型 / 表示 | 正在被生成或编辑的对象，也就是结果 | NeRF 表示、可导出的三角网格 |

三维表示本身也可能由神经网络存储，但它与预训练图像大模型的角色不同。不是把一个大模型“变成”另一个三维文件，而是借用前者指导后者的构建。

**运行前加载大模型；运行时输入文字或图片；运行后得到三维结果。** 模型权重文件虽然也是程序读取的数据，但对使用者而言，它属于环境准备，不应与每次任务的素材混在一起。

## 用捏泥巴理解工作过程

想象要制作一只小猫：预训练图像模型像一个熟悉猫的外观的老师，三维表示像一团可调整的数字泥巴，算法决定如何根据反馈修改泥巴，渲染器负责从不同方向给泥巴拍照。

1. 创建一个还没有成形的三维表示。
2. 从某个角度把它渲染成二维图片。
3. 把图片与“小猫”的要求交给图像模型，得到修改方向。
4. 利用这个方向调整三维对象的形状与外观。
5. 换一个角度，再次渲染、反馈和修改，直到达到配置的结束条件。

“老师说耳朵应该变尖”只是便于理解的比喻。实际传递的是数值信号，模型不会给算法发送一段口头雕刻指令。

## 实际原理：从二维指导到三维更新

以 `configs/dreamfusion-sd.yaml` 为例，它选择 Stable Diffusion 2.1 base 作为引导模型，使用隐式体表示和 NeRF 体渲染器，默认进行 10,000 步优化。这是该固定配置的设置，不是所有方法或所有生成任务的统一要求。[配置证据](https://github.com/threestudio-project/threestudio/blob/28d9d80d9d00f308244adfcf3be8b17ca0cb6465/configs/dreamfusion-sd.yaml)

典型的 SDS（分数蒸馏采样）过程如下：

1. **渲染**：从三维表示得到当前视角的 RGB 图像。
2. **编码与加噪**：在 Stable Diffusion 路线中，用 VAE 将图像编码到潜空间，再加入随机噪声。
3. **条件预测**：扩散模型依据文字条件和噪声水平预测噪声。
4. **构造更新信号**：用预测噪声与实际加入噪声的差异，结合权重形成指导梯度。
5. **更新三维参数**：经图像编码器和可微渲染链路，把指导传回三维表示；系统还可加入几何正则项，帮助约束形状。

该实现不是先独立生成大量完整图片再简单拼接，也不是只给当前图片打一个“猫 / 非猫”的分类标签。关键是生成可用于更新对象的方向。[指导实现](https://github.com/threestudio-project/threestudio/blob/28d9d80d9d00f308244adfcf3be8b17ca0cb6465/threestudio/models/guidance/stable_diffusion_guidance.py) · [训练循环](https://github.com/threestudio-project/threestudio/blob/28d9d80d9d00f308244adfcf3be8b17ca0cb6465/threestudio/systems/dreamfusion.py)

在这条路线中，Stable Diffusion 的 VAE、去噪网络权重被冻结；VAE 权重不更新不代表图像编码过程不能把梯度传回输入。优化器更新的是配置指定的三维表示等参数。所检查的 DreamFusion 配置显式为 geometry 和 background 设置了学习率。

不能把“大模型始终完全不训练”推广到整个仓库：ProlificDreamer 的 VSD 路线涉及额外 LoRA 学习；其他方法也可能采用不同指导方式、表示和优化阶段。[方法差异](https://github.com/threestudio-project/threestudio/blob/28d9d80d9d00f308244adfcf3be8b17ca0cb6465/README.md#prolificdreamer-)

## 输入、能力与输出

| 任务 | 输入条件 | 处理方式 | 输出与需要理解的边界 |
| :--- | :--- | :--- | :--- |
| 文字生成 3D | 一段描述 | DreamFusion、Magic3D、ProlificDreamer 等指导三维优化 | 三维对象；部分方法有场景配置，效果和完整性需验证 |
| 单图生成 3D | 参考图，常用去背景 RGBA 图 | Zero123 / Stable Zero123 用图像与视角条件提供指导 | 推测包括不可见视角在内的三维外观，不保证还原真实背面 |
| 图片加文字生成 | 图片与描述 | Magic123 结合图像视角先验和文字图像先验 | 本仓库的 Magic123 实现要求文字，未支持 Textual Inversion |
| 文字指令编辑 | 方法要求的场景数据与指令 | InstructNeRF2NeRF、Control4D 静态路线 | 编辑场景外观，不能理解为任意上传的网格均可直接修改 |
| 几何 / 纹理细化 | 前阶段三维结果或检查点 | Magic3D、ProlificDreamer 的后续阶段 | 再优化形状或纹理；每阶段要有对应配置和依赖 |
| 测试与导出 | 三维结果 / 检查点 | 渲染测试、网格提取、纹理导出 | 多角度图、360° 视频、OBJ + MTL 与纹理，或带顶点颜色的 OBJ |

图片分辨率、相机设置、前处理和所需数据随方法变化。所谓“输出三维模型”并不代表每个方法一步直接输出同一种文件：NeRF 等表示通常要经过网格提取才能成为 OBJ。[支持方法与导出](https://github.com/threestudio-project/threestudio/blob/28d9d80d9d00f308244adfcf3be8b17ca0cb6465/README.md)

## 能力覆盖与边界

- **科研与二次开发**：统一配置和可替换模块适合复现方法、比较算法和加入新的指导方式。
- **资产草稿与创意设计**：可尝试道具、摆件、玩具等造型；进入后续美术流程仍需检查网格、材质和质量。
- **工具原型**：可以作为 GPU 生成后端的基础，仓库还提供 Gradio 界面；稳定服务仍需要任务管理、资源调度和结果处理。
- **精确工程与真实复刻**：不可见面由模型推测，不能保证尺寸、拓扑或制造可用性。

这些场景是本研究的应用判断，不是已验证的生产案例。

部分方法为实验性或非官方复现。上游明确说明生成不能持续稳定地产出令人满意的结果，存在多面脸、几何或纹理异常等问题。算力开销随方法、步数、分辨率和显存策略变化，本次没有测量速度、质量和成本。

扩展列表包含高斯表示、动态 4D、人物等方向，需进入对应扩展单独安装与核对。固定版本核心的 Control4D 示例明确只支持静态编辑，不能把其名字中的“4D”理解成当前实现已经支持动态编辑。[固定版本边界](https://github.com/threestudio-project/threestudio/blob/28d9d80d9d00f308244adfcf3be8b17ca0cb6465/README.md#control4d-)

## 常见问答

**它自己提供大模型吗？** 提供模型接入和相应配置，通常需要另行取得第三方预训练权重。仓库算法代码和模型权重是不同交付物。

**模型负责识别，算法负责生成吗？** 更准确的说法是模型提供视觉知识与生成指导，算法把指导落实为三维更新。分类识别不足以描述这里的模型作用。

**输入是模型还是图片？** 大模型属于运行前的工具；图片或文字属于具体任务的输入。场景编辑另需相应场景数据。

**运行时要自己训练一个大模型吗？** 典型 DreamFusion 路线无需从头训练图像大模型，但要为当前对象进行迭代优化；其他路线可能额外训练 LoRA 等组件。

**能不能直接得到可用文件？** 仓库提供网格导出，文件能否直接进入游戏、美术或制造流程仍需实际检查。也不能把环绕视频理解为对象自带动画或骨骼。
