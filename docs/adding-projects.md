# 新增研究项目

## 1. 分配编号

查看[首页索引](../README.md#项目索引)和现有项目目录，使用历史最大编号加一。首个项目使用 `001`，目录示例为 `projects/001-example/`。

## 2. 复制模板

将整个 `templates/project/` 复制到新项目目录。例如在仓库根目录执行 PowerShell：

```powershell
Copy-Item -LiteralPath templates/project -Destination projects/001-example -Recurse
```

将 `001-example` 替换为实际编号与名称，执行前确认目标目录不存在。模板中的相对链接按正式目录层级设计，复制后可以直接使用。

## 3. 填写项目介绍

替换子项目 README 的占位内容，至少填写原始仓库、研究版本、许可证信息、收录日期、研究状态与一句话摘要。尚未验证的内容明确保留为待研究。

长篇分析写入 `notes/`；Web 演示按需放入 `web/`，并补全本地运行说明。

## 4. 登记首页索引

在根 README 的 `PROJECT_INDEX_START` 与 `PROJECT_INDEX_END` 之间添加一行，首次添加时移除“暂无项目”行：

```markdown
| 001 | [项目名称](projects/001-example/README.md) | [owner/repository](https://github.com/owner/repository) | 一句话说明用途与研究重点 | 待研究 | — |
```

列顺序为：编号、研究项目、原始仓库、摘要、状态、在线演示。项目名称链接到本地研究说明，原始仓库列直接链接到上游仓库，并将示例中的 `owner/repository` 替换为真实地址。按编号升序排列。首页只放摘要，避免重复完整研究内容。

## 5. 添加图片与演示

将真实截图放入子项目 `assets/`，再更新子项目图集与首页预览。首页每个项目放一张代表性图片，预览按编号升序排列，并链接到研究详情。

部署完成、实际访问验证通过后，更新首页与子项目的演示链接。尚未部署时保留 `—`。

## 6. 提交前检查

- 编号唯一，目录、首页索引与预览顺序一致。
- 项目链接和图片相对路径可用，未保留误导性的占位链接。
- 研究版本明确，结论与实际验证情况一致。
- 未提交依赖目录、构建产物、本地配置或密钥。
- 引用的代码、文字和图片有来源与许可证记录。
